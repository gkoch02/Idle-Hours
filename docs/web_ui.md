# Curator web UI (`web_server.py`, `idle_hours/web/`)

Full reference for the optional curator HTTP UI: endpoints, security model,
and curation semantics. Moved out of `CLAUDE.md` (which keeps a summary).

## Curator Web UI (`web_server.py`, `idle_hours/web/`)

Optional in-process HTTP surface for browsing telemetry / coverage / candidates and curating the corpus end-to-end without SSHing into the appliance. As of v2 the UI is the full curation seat: it edits both override sidecars, re-bakes the runtime database, runs full-text search across the corpus, renders side-by-side theme previews, and surfaces empty/sparse buckets with phrase suggestions for the harvester. **Off by default** — only starts when `run_clock.py --web-bind HOST:PORT` is passed. Served from a `ThreadingHTTPServer` on a daemon background thread so the main render loop doesn't share an event loop with HTTP, but the two threads share `state.render_lock` / `state.lock` / `state.ledger_lock` via the same `RuntimeState` instance. **In-process is non-negotiable**: every mutating POST routes through the same `_button_render_gate` (non-blocking `render_lock.acquire`) that GPIO button handlers use, and atomic state/override writes are only safe when one process owns the file.

**Lifecycle.** `run_clock._maybe_start_web_server(args, state)` runs after `_maybe_start_buttons`, imports `web_server` lazily (so unit tests and `--buttons-off` dev hosts never pay for it), and calls `web_server.start_web_server(args, state, token=...)`. The `(server, thread)` handle is stashed so `stop_web_server` can be called by tests for deterministic teardown; the daemon thread flag means the process's own exit tears it down automatically under systemd. A startup failure (malformed bind, port busy, missing token on non-localhost bind) is **logged but not fatal** — the panel keeps rendering.

**Action handlers are shared with buttons.** Each GPIO button's body has been hoisted from `_build_button_handlers` closures into module-level `run_clock.action_skip` / `action_unskip` / `action_theme` / `action_quiet` / `action_rerender` functions. The button dispatcher and the HTTP handler both call them with a `label="button A"` or `label="web"` attribution string. Each function returns `{"ok": True, ...}` on success, `{"ok": False, "error": "busy"}` when the render lock is held, or `{"ok": False, "error": "<repr>"}` on exception; the web handler maps that to 200 / 409 / 500. The source-card restore timer and the shutdown command remain inline in `_build_button_handlers` because neither fits the single-response return-dict contract.

**Endpoints.**

```
# Static
GET  /                                → web/index.html
GET  /main.js, /style.css             → web/main.js, web/style.css
GET  /current.png                     → streams output/current.png

# State + telemetry (read-only)
GET  /api/current                     → {time, bucket, theme, source_id, line_number, ...}
GET  /api/telemetry?hours=24          → {render_count, error_count, p50/p95 latencies, last_error}
GET  /api/coverage                    → live coverage computed from the raw corpus
                                          (falls back to assets/bucket-coverage.json)
GET  /api/themes                      → {themes: [...THEME_ORDER], theme_arg, manual_theme, effective}
GET  /api/history?limit=N             → anti-repeat ledger entries, newest-first,
                                          joined against the corpus for quote text
GET  /metrics                         → Prometheus text-format scrape over a 24h window (v2)
GET  /api/setup                       → {setup_complete, themes, quiet_start, quiet_end, ...} (v2; first-run wizard status)

# Curation (read)
GET  /api/bucket/<bucket>?time=HH:MM&top=N → ranked candidates with named score components
GET  /api/overrides                   → assets/selection_overrides.json (defaults ban_quote_keys=[])
GET  /api/content-overrides           → assets/content_overrides.json (v2; fail-open on corrupt file)
GET  /api/search?q=&author=&title=&bucket=&limit=N
                                      → linear-scan search across the raw corpus (v2)
GET  /api/gaps?threshold=N            → empty / sparse buckets + phrase suggestions
                                          from target_sparse_buckets.STATE_TEMPLATES (v2)
GET  /api/preview?theme=&time=HH:MM&width=&height=&mode=
                                      → image/png of the picker's pick rendered in any theme,
                                          history disabled for determinism (v2)

# Curation (write)
POST /api/overrides                   → validate + atomic rewrite (now accepts ban_quote_keys);
                                          honours If-Match against the ETag GET returns (412 on a
                                          stale save; no If-Match = unconditional, for scripts)
POST /api/overrides/ban               → {"key": "<source_id>:<line_number>"}: server-side append
                                          to ban_quote_keys under a lock; 409 (never a clobber) when
                                          the file exists but does not parse (#289)
POST /api/content-overrides           → validate + atomic rewrite of the per-row sidecar (v2);
                                          empty {} is a legitimate "wipe everything"
POST /api/bake                        → run bake_quote_database.bake_rows in-process under
                                          render_lock; re-applies the content-overrides sidecar
                                          first so save → bake reflects on the next tick (v2);
                                          409 when busy
POST /api/setup                       → mark first-run wizard complete; optional {"theme": "<name>"}
                                          body applies a theme before dismissing (v2);
                                          flips state.setup_complete to True and persists
POST /api/action/{skip,unskip,theme,quiet,rerender} → mirror physical buttons
     (theme accepts optional {"theme": "<name>"} body to jump directly;
      empty body / missing field advances one step through THEME_ORDER)
```

**Security model.** Loopback binds (`127.0.0.1:*`, `localhost:*`, `::1:*`) run without auth — the OS-level trust boundary is sufficient for a single-operator home appliance. Any other bind **requires** `--web-token` or `--web-token-file`; `start_web_server` raises `ValueError` if you try to bind `0.0.0.0` without one, so an operator can't accidentally expose a tokenless POST surface. Tokens are checked against the `X-Idle-Hours-Token` header only — never query strings, which `BaseHTTPRequestHandler` logs to stderr and journald. `_check_token` uses `hmac.compare_digest` for timing-safety. Unknown routes return 404 **before** the auth check — for GETs as well as POSTs — so a scanner's wrong-token probe doesn't learn the service exists. `--web-token-file` is preferred over `--web-token` in production so the secret doesn't show up in `ps`/journald.

**What the token gates (v2.x, issue #233).** A configured token now gates every POST **and** every JSON GET — `/api/current`, `/api/telemetry`, `/api/coverage`, `/api/gaps`, `/api/themes`, `/api/setup`, `/api/overrides`, `/api/content-overrides`, `/api/search`, `/api/history`, `/api/bucket/*`. Previously GETs were open on every bind, so anyone on the LAN could read the display history (which is reading habits), the whole corpus via `/api/search` + `/api/bucket/*`, and both override sidecars. The justifying comment ("the UI fetches them without credentials") was simply inaccurate — `main.js`'s `jsonFetch` attaches `X-Idle-Hours-Token` to every request, GETs included — so gating them costs the UI nothing.

Three routes stay open, and the reason is mechanical rather than editorial: a `<script src>` / `<link href>` / navigation **cannot attach a request header**, so gating the static shell (`/`, `/main.js`, `/style.css`) would break the page rather than protect anything. `/metrics` is a scraper's and stays open by default so an existing Prometheus job keeps working; `--web-metrics-token` gates it too. `UNGATED_GET_PATHS` is the list; extend it only for another route a browser loads by tag.

**The two image routes are gated too (issue #286).** `/current.png` and `/api/preview` were exempt on the same `<img src>` reasoning, but on a LAN bind with a token that left the picker's winning quote for every minute of the day, in every theme, readable by anyone on the network — with `mode=card` giving title / author / Gutenberg ID — and each distinct `(theme, mode, width, height, time)` a full Pillow render, unbounded because `mode` was taken verbatim and so bypassed the preview cache at will. `main.js` now fetches both routes through `authFetch` (the one place a request leaves the page with credentials; `jsonFetch` is built on it) and assigns the bytes to the tag as an object URL via `loadImage`, revoking the previous URL so the 30 s `/current.png` poll does not leak a frame per refresh; thumbnails go through `loadImageWhenVisible`, an `IntersectionObserver` that replaces the old `loading="lazy"` attribute so the grid still renders a theme only when it scrolls into view. The CSP's `img-src 'self' blob:` exists for this. `/api/preview` also validates `mode` against `PREVIEW_MODES` (`production` / `debug`, 400 otherwise): the two modes the panel itself shows, and nothing that would key another cache entry.

**CSRF / DNS-rebinding defence (v2.x, issue #233).** On the deployment the docs recommend — `--web-bind 127.0.0.1:8080`, where loopback binds skip auth entirely — **any web page the operator visited could drive the appliance**: flip quiet mode, cycle the theme, skip/ban the displayed quote, rewrite both override sidecars, trigger a bake. Each also burns a 10–20 s Spectra 6 refresh, and `/api/action/skip` bans the displayed quote permanently.

The token is genuinely CSRF-resistant *where it applies* — a custom header forces a CORS preflight an attacker can't satisfy — but `_check_token` short-circuits on `if not token: return True`, so a loopback bind has no header requirement and loses that property, and `_read_json_body` used to `json.loads` the body regardless of `Content-Type`, so a cross-site **simple request** (`text/plain`, or a plain `<form>`) had nothing to preflight. Three independent server-side layers close it, applied in that order before the token check so a probe learns nothing from the difference between "wrong token" and "no token":

1. **`Content-Type: application/json` required on every POST** (`_check_json_content_type`, 415 otherwise) — including a bodyless one, because `fetch(url, {method:'POST'})` with no body sends no Content-Type and is therefore a simple request; that is exactly how `POST /api/bake` was reachable from any open page. `application/json` is not CORS-safelisted, so requiring it forces a preflight, and the server answers no `OPTIONS` — the real request is never sent. **Behaviour change for scripts:** a bare `curl -X POST .../api/bake` now returns 415; add `-H 'Content-Type: application/json'`. `main.js`'s bake button was updated to send it.
2. **`Origin` compared against the request's own `Host`** (`_check_origin`, 403 on mismatch or on the literal `null` a sandboxed iframe / `file://` sends). Comparing the two *request headers against each other* — rather than against a configured name — is the load-bearing detail: an operator may reach a LAN bind by IP, mDNS name, or reverse-proxied name, and we cannot enumerate those, but every one of them still produces `Origin.host == Host` while a genuine cross-site page cannot. An absent `Origin` is allowed (curl, the health cron, same-origin GETs).
3. **`Host` validated against the bind** (`WebContext.host_is_allowed`, 403 otherwise), on GETs as well as POSTs. This is the layer that closes DNS rebinding — an attacker-controlled name resolving to `127.0.0.1` arrives as a *same-origin* page, defeating layers 1 and 2 outright — and the only one that protects the read surface. A **loopback bind is strict**: loopback names only, plus `--web-allowed-host` entries (repeatable; config key `web_allowed_hosts`, a TOML array — the CLI flag *replaces* a configured list rather than appending to it, via `_ReplaceConfigDefaultAppend`, so the allowlist can be tightened from the command line; plain `action="append"` copies the config default and appends, which would leave a host an operator meant to revoke still authorised). A **non-loopback bind stays permissive** unless an allowlist is configured, because we can't enumerate the names an operator uses to reach `0.0.0.0` and rejecting them would break every existing LAN install on upgrade; those binds require a token regardless, and a rebound origin gets its own `localStorage` and so has no token to replay. Hostname only is compared, never the port, so a port-rewriting reverse proxy still works.

An absent or empty `Host` is rejected outright rather than treated as "no opinion". The Host check originally reused `LOCALHOST_HOSTS`, whose `""` member exists for `_parse_bind`'s empty-*bind*-host normalisation — an unrelated meaning that let a Host-less HTTP/1.0 request through both guards and mutate state. Never reachable from a browser (which always sends Host), so not a CSRF hole, but an accidental bypass resting on a coincidence that would have broken in whichever direction that member later changed; the check now has its own `LOOPBACK_HOST_NAMES` frozenset plus an explicit empty-name rejection. The explicit rejection is load-bearing only on a *non-loopback* bind, where the permissive path ends at `return not self.allowed_hosts` — on a loopback bind an empty name simply isn't in the set.

All three rejections write a `mode="web_error"` telemetry entry with `status` and `path`, so an operator can see a page probing their appliance in `idle-hours health --actions-only`. Note this makes three more pre-auth telemetry writers reachable by an unauthenticated caller; the class is not new (`web_auth_fail` was always pre-auth by construction) but the surface is wider, so an attacker who can reach the port can drive fsynced disk writes at request rate.

**One UI consequence of gating GETs.** `refreshAll()` fires five gated GETs through `Promise.all` and the wizard adds `/api/setup`, so on a LAN bind's very first load six independent 401 handlers each raised their own `window.prompt` — six stacked dialogs. `promptForToken(staleToken)` now takes the token the failed request actually used and adopts whatever storage holds if a sibling handler has already prompted, so one dialog serves the whole page load while the other five retry silently. Keying on *"storage changed"* rather than *"storage is non-empty"* is what keeps a stale saved token correctable. Storage is not the only evidence, though: cancelling the dialog (or submitting an empty value) stores nothing, so the attempt itself is memoised in `tokenPromptAttempt` — otherwise all six dialogs returned precisely when the operator did not have the token to hand. `inFlightRequests` scopes that memo to one burst, so a request starting when nothing else is in flight can prompt again rather than being silenced for the life of the page. The prompt text no longer says "for write operations" — reads trigger it too now.

**Token hot-reload.** When `--web-token-file` is configured, `WebContext.current_token()` stats the file on every request and re-reads it when `st_mtime` changes, so rotating the secret is a plain file replace — no `systemctl reload` needed. The stat + read is serialised under `WebContext._token_lock` so racing requests can't interleave a partial string into the cached token. If the file goes briefly unreadable (e.g. the operator mid-replace), the previous cached value is returned rather than dropping auth entirely — the replacement is picked up on the next successful stat after the file reappears. Auth failures during the gap surface as `mode="web_auth_fail"` telemetry entries.

**Connection limits (issue #285).** The server runs inside `run_clock`, so a client that exhausts its threads or file descriptors breaks the appliance's own state, telemetry and PNG writes, not just the UI. Three bounds apply: `CuratorHandler.timeout` (30 s per socket read), `_IdleHoursHTTPServer.max_connections` (16 live connections; one more is closed unread and counted in `dropped_connections`), and `connection_deadline` (120 s total per connection, enforced by a timer that shuts the socket down from outside and counted in `expired_connections`). The deadline exists because the read timeout restarts on every byte: a client trickling one byte every 29 s never timed out, and sixteen of them locked the UI and `/metrics` out indefinitely.

**Shared utilities, no duplication.**
- Atomic writes go through `atomic_io.atomic_write_text` / `atomic_write_bytes` / `atomic_write_lines` (tmp → fsync → `os.replace` → dir fsync), the single durability primitive shared between `save_runtime_state`, `web_server.write_overrides_atomic`, the rendered-PNG writer in `render_quote`, the ledger-rewrite path in `pick_quote.remove_history_entries`, and the corpus writeback in `apply_content_overrides`.
- Bucket validation uses `pick_quote.valid_bucket_names()` so `POST /api/overrides` rejects the same bad keys that `load_overrides` warns about.
- Telemetry summarisation reuses `idle_hours_health.load_entries` and `idle_hours_health.summarise` directly — the endpoint does not reimplement date-window globbing.
- `pick_quote.pick_best(..., return_ranked=True)` and `pick_quote.select_candidates(...)` are the single entry point for the bucket-inspector view; the UI projects the raw `score_row` tuple into named fields via `SCORE_COMPONENTS` so the operator can see "lost by minute_penalty=8" rather than a mystery integer.

**Static assets.** `idle_hours/web/index.html` + `idle_hours/web/main.js` + `idle_hours/web/style.css` are plain HTML/JS/CSS, **no build step** and no framework. Resolved via `BASE_DIR / "web"` so the service file doesn't depend on CWD. `main.js` polls `/api/current`, `/api/telemetry`, and `/api/themes` every 30s; the coverage grid and overrides editor load once and refresh on click. The theme dropdown rebuild skips when it has keyboard/mouse focus so a polled refresh can't clobber an open selection, and the theme-state pill distinguishes three runtime shapes: `manual: X` (override active), `auto: X` (wall-clock-derived), and `fixed: X` (explicit `--theme X` pin with no manual override).

**Mobile-first layout (v2).** The UI is organised as four tabs — **Now** (preview + button mirrors + theme thumbnail grid), **Curate** (search, bucket inspector, dual-sidecar editors, bake button), **Coverage** (12×12 grid + gap finder), **Activity** (telemetry + history). CSS is mobile-first with two breakpoints (768px tablet widens form rows, 1024px desktop puts the Now tab into a two-column layout); buttons and inputs honour the iOS HIG 44px minimum tap target so a phone-on-the-counter operator can curate without zooming. Tabs are kept in `location.hash` so a bookmark like `idle-hours.local#curate` jumps straight to the editor. Lazy loads: content-overrides + the gap finder + the theme preview grid are only fetched on first activation of their tab — first paint stays snappy on slow phones over LAN. The four tab-state booleans live on a module-level `state` object; tab switches don't re-fetch the same data.

**First-run setup wizard (v2).** A modal overlay shown on the very first visit to a fresh appliance — gated by `state.setup_complete` (a new `bool` field on `RuntimeState`, persisted to `state.json` alongside `manual_theme` / `manual_quiet`). The wizard has three steps: (1) a `/api/preview`-driven theme thumbnail grid where tapping a theme applies it via the same `action_theme` path the dropdown uses; (2) a read-only summary of the configured quiet hours so the operator knows when the panel will sleep; (3) a "I'm ready" button. POST to `/api/setup` flips `setup_complete=True` and persists; subsequent loads skip the overlay entirely. Quiet hours stay configured via `--quiet-start` / `--quiet-end` because dynamic runtime quiet-window changes would need a state-machine refactor we deferred to v2.x — for v2.0 the wizard is intentionally just the discovery surface for the existing knobs.

**Prometheus `/metrics` endpoint (v2).** Standard text-exposition format (Prometheus 0.0.4) over a fixed 24 h window — configurable per-window aggregation belongs on the scraper side via `rate()` / `increase()`, not on the exporter. Reuses `idle_hours_health.load_entries` + `idle_hours_health.summarise` so the exposed values match `idle-hours health --json` exactly; no parallel aggregation logic to drift. Stays open without auth on every bind (matches the rest of the GET surface) so a Prometheus scraper running on the same LAN can hit it without managing a token. Operators who care bind to 127.0.0.1. Metrics emitted: `idle_hours_renders_total` / `idle_hours_errors_total` / `idle_hours_heartbeats_total` / `idle_hours_actions_total` / `idle_hours_press_dropped_total` / `idle_hours_web_auth_fails_total` / `idle_hours_web_errors_total` / `idle_hours_quiet_enter_total` / `idle_hours_quiet_exit_total` (gauges over the window — we don't have process-lifetime monotonic counters), `idle_hours_render_p50_ms` / `idle_hours_render_p95_ms` / `idle_hours_display_p50_ms` / `idle_hours_display_p95_ms` (latency gauges; missing values omit the sample line), `idle_hours_last_heartbeat_age_seconds` (the loop-liveness alert metric — fires when the loop wedges), and `idle_hours_last_render_age_seconds` (the "panel is stale" alert metric — fires when the loop is alive but no longer repainting). Both age gauges follow the same missing-value convention as the latency gauges: `HELP`/`TYPE` are always emitted and only the sample line is omitted, so a fresh or idle appliance doesn't make the series disappear entirely.

**Webhook fan-out (v2, `runtime_webhook.py`).** `--webhook-url URL` posts a JSON body for each alert-worthy telemetry event. Default filter (`runtime_webhook.ALERT_MODES`): errors, `backoff`, `render_timeout`, `display_timeout`, `shutdown_timeout`, `buttons_dead`, `state_validation`, `web_auth_fail`, `web_error`. **Heartbeats and successful renders are always filtered**, because alerting once a minute is spam, not signal — even when `--webhook-all-events` widens the filter. The fan-out is fire-and-forget on a daemon thread with a 5 s `urllib.request.urlopen` timeout, so a wedged endpoint never blocks the render loop. Failures log to stderr as `webhook: …` but never raise. **At most `_WEBHOOK_MAX_INFLIGHT` (4) posts are in flight at once, and events over that cap are dropped, not queued** — a non-blocking `BoundedSemaphore` acquire gates each new thread, so a fault storm against an unresponsive endpoint can't grow an unbounded thread pile. There is no backlog, no retry, and no ordering guarantee; treat the webhook as "alert me", not as delivery. Anything that must not be lost stays in the telemetry sidecar, which is written synchronously and fsynced. (A `ThreadPoolExecutor` would give ordering and a bounded backlog, but its workers are non-daemon and would block process exit against exactly the wedged endpoint the timeout guard exists for.) Configuration is module-level (`runtime_webhook.configure(url, all_events=...)`) and set once at `run_clock.main` startup; `runtime_telemetry.append_telemetry` reads it via lazy import so the no-webhook path pays no import cost. Tests reset the global between cases via an autouse fixture.

**No-op guard on `action_theme`.** The web dropdown pre-selects the active theme, so a "click Apply without changing anything" would otherwise burn a 10–20 s Spectra 6 refresh. Worse, if `manual_theme` was `None` (because `--theme auto` is running) and the target equals the auto-resolved value, setting `state.manual_theme = target` would silently pin auto mode off until the next midnight reset. `action_theme` returns `{"ok": True, "noop": True}` without mutating state when `target is not None and target == current_effective`. The button-B cycle path (`target is None`) deliberately bypasses the guard so it always advances.

**v2 closes the v2.1 carve-out.** The earlier scope boundary — "the curator UI doesn't edit `content_overrides.json`, and there's no way to ban a single row" — is gone. `POST /api/content-overrides` writes the per-row sidecar; `POST /api/bake` re-runs the baker in-process so the runtime picker sees the patched rows on the very next tick (no SSH session, no separate CLI step). Per-row bans land on the same flow: `ban_quote_keys` on the selection-overrides sidecar drops a single `(source_id, line_number)` row, and the UI's "Ban this quote" buttons (Now tab, bucket inspector, search results, history) send just the key to `POST /api/overrides/ban`, which does the read-modify-write server-side under the same lock the editor's `If-Match` save takes (issue #289 — the browser-side GET → mutate → POST lost any write landing between the two requests). The ban merges the key into the *loaded* document, so unknown keys and id types survive, and it refuses (409) only a file it cannot parse. ETags are a hash of the exact bytes written, compared with any `W/` a compressing reverse proxy added stripped off; `GET /api/overrides?envelope=1` also returns the ETag in the body, which the page prefers over the header. A 412 keeps the operator's draft in the editor and shows the on-disk version beside it, and a ban never overwrites unsaved editor text.

**History entries are joined against the corpus (issue #197).** The ledger stores only `(ts, source_id, line_number)`, so the Activity tab could render nothing better than "source 141 line 482" — meaningless to an operator asking "what has the clock shown this week?". `_api_history` builds a `{(source_id, line_number): row}` index over *just the rows on the requested page* and attaches `display_quote` / `author` / `title`, so the UI shows readable history and the "Ban" button falls out for free via the existing `banQuoteKey` flow. Joining server-side keeps the corpus off the wire and reuses the stat-keyed row cache. Two deliberate choices: entries whose row no longer exists (dropped by a re-bake, or removed outright) are returned with their IDs alone rather than omitted — the ledger is a record of what *was* displayed, and hiding an entry because its source row moved would misrepresent that history; and the join reads the RAW corpus so an entry stays readable after a re-bake drops its row below the quality floor. `(source_id, line_number)` is not unique in the corpus (one source line can carry several time phrases) and the ledger doesn't record which phrase was shown, so the index is first-wins — the duplicates share the quote text, which is what the operator is reading.

**Coverage is computed live, not served from the snapshot.** `GET /api/coverage` and `GET /api/gaps` call `bucket_coverage.build_summary` over `ctx.raw_corpus_path` (via `pick_quote.load_rows_cached`, so a repeat request against an unchanged corpus costs one stat plus a ~2 ms summary walk). They previously served `idle_hours/assets/bucket-coverage.json`, a *build-time* artifact — which made both views wrong in exactly the moments an operator consults them: a ban or a "Bake now" changes which rows the picker can reach and the snapshot never moved, and on a relocated `--raw-corpus` deployment (the shipped systemd preset, issue #179) the snapshot described the *bundled* corpus rather than the live one (issue #194). The committed snapshot remains as a fallback for a missing or unreadable corpus; responses carry `live: bool` and `source: <path>` so the UI can say which it got. Reads the RAW corpus, but **counts what the panel can display (issue #300)**: `bucket_counts` — and everything derived from it (populated / empty / sparse / `coverage_percent`) — apply the baker's gates — a non-blank `display_quote` once the cleaner has set one, and the quality floor (`DEFAULT_MIN_QUALITY`, 60) — and the live bans from `selection_overrides.json`, including the textual twins a `ban_quote_keys` entry reaches in the picker (`banned_twin_texts`), with the raw tallies kept alongside as `raw_bucket_counts` / `raw_populated_bucket_count`. Before that the coverage grid, the gap finder and the committed snapshot counted every raw row with a bucket, so five buckets whose only row scored below the floor were reported "covered" while the panel rendered a neighbour-bucket fallback for them, and the snapshot said 22 empty buckets against a runtime 27. `is_displayable` is the single definition of the gate. A row with no `display_quote` key at all still counts, as a row with no score does: coverage also runs on merged, pre-clean candidates to choose the sparse buckets to target, and gating those would read every bucket as empty; `/api/gaps` adds a `tier` (`empty` / `thin` ≤2 rows, where the anti-repeat ledger falls back to the full list / `sparse`) and the CLI takes `--min-quality` / `--overrides` so the committed snapshot is generated with the same rule.

**v2 search and gap-finder.** `GET /api/search` is a stdlib linear scan across the raw corpus (~3K rows, <50 ms) supporting `q` / `author` / `title` / `bucket` filters in any combination — at least one is required, all are case-insensitive substring. Hard-caps `limit` at 500 to bound response sizes. Reads the raw corpus (not the baked DB) on purpose so an operator searching for "where did that quote go?" can find rows the baker dropped (low quality / daypart-only) and understand why they're not appearing. `GET /api/gaps` joins each below-threshold bucket against `target_sparse_buckets.STATE_TEMPLATES`, so the suggested phrases match what `target_sparse_buckets.py --search-dir data/gutenberg` would actually look for if invoked from the CLI.

**Theme preview endpoint.** `GET /api/preview?theme=...&time=HH:MM` calls `pick_quote.select_quote` (history disabled for determinism), feeds the result into `render_quote.render`, and streams the PNG bytes back. The Now tab's theme thumbnail grid issues one request per registered theme so an operator can compare every operator-choice theme (all of them but the `diags` swatch panel) side-by-side on the actual current quote before applying. Width/height are clamped to `800×480` so a hostile/buggy client can't request a slow or high-memory render. Does not touch the panel and never commits to `state` — preview is intentionally side-effect-free.

**`POST /api/bake` semantics.** Runs `bake_quote_database.bake_rows` in-process; non-blocking acquire of `render_lock` returns 409 (busy) when a render is already in flight rather than queueing behind a 10–20 s Spectra 6 refresh. Re-applies `idle_hours/assets/content_overrides.json` to the raw corpus *before* baking so a UI workflow of "edit row → save → bake" round-trips edits onto the panel within seconds — and **writes the patched rows back to the raw corpus** (issue #288), matching the CLI stage, whose in-place writeback is what "re-apply" means there. The bake used to patch an in-memory copy and write only the baked DB, while every curator read surface (`/api/bucket`, `/api/search`, the history join, the coverage grid) reads the raw corpus: after save → bake the panel showed the patched quote and the inspector the old text, so the operator concluded the save had not landed. The overrides stage runs even with an empty sidecar, because that is how a deleted override is reverted (see `override_originals` above); the raw write is skipped when no row actually changed (a repeat bake is a no-op on the SD card) and goes through `atomic_write_lines` under the same `render_lock`. The runtime picker reads the baked DB from disk on every `select_quote` call (it goes through `_resolve_corpus`), so no in-memory cache invalidation is needed — the next tick picks up the new file automatically. Stats are returned in the response (`kept` / `input` / `applied_overrides` / `reverted_overrides` / `drops` / `per_bucket`) so the UI can render an operator-readable summary.
