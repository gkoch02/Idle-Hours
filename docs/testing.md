# Testing & CI

Full reference for the test suite, the fence tests, and the CI jobs. Moved out
of `CLAUDE.md` (which keeps a summary).

## Testing

The test suite lives in `tests/` and uses pytest with pytest-cov / pytest-xdist. There are 52 test modules covering every pipeline script plus the runtime components — ~4180 collected test cases at last count (post-parametrize expansion) (including `test_bake_quote_database.py` for the display-ready DB baker, `test_bake_equivalence.py` which sweeps all 144 canonical buckets to prove baked picks match raw-corpus picks, `test_baked_db_schema.py` for the schema_version contract, plus dedicated suites for the appliance-hardening modules: `test_pidfile.py`, `test_sd_notify.py`, `test_web_server.py`, `test_contact_sheet.py`, `test_buckets.py`, `test_jsonl_io.py`, and `test_packaging.py`). `tests/test_atomic_io.py` exercises the shared durability primitive (`atomic_write_text` / `_bytes` / `_lines`) including monkeypatched `os.replace` failure paths that assert the tmp sibling is cleaned up and the target file is left byte-identical. The reliability branches of every caller are covered in their respective modules: `test_pick_quote.py` for the ledger-rewrite atomicity, `test_apply_content_overrides.py` for fail-open loading and atomic corpus writeback, `test_render_quote.py` for PNG-save crash recovery, `test_run_clock.py` for `_install_signal_handlers` / `_shutdown` / `prune_telemetry` / `_maybe_prune_telemetry`. Cross-cutting suites include `test_pipeline_integration.py` (end-to-end pipeline smoke), `test_corpus_invariants.py` (committed-corpus sanity checks), `test_miner_match_types.py` (regex per match type), `test_buckets_properties.py` (hypothesis-style bucket invariants), `test_concurrency.py` (render-lock and ledger-lock contention), `test_sleep_frame.py` (the quiet-hours sleep frame and `--quiet-theme` — spanning `render_quote` / `runtime_theme` / `runtime_quiet` / `runtime_actions`, with the byte-identity fence against the bundled `goodnight.png` that justified flipping the `--quiet-image` default), and `test_cli_main_smoke.py` (each script's `if __name__ == "__main__"` entrypoint). `display_inky.py` is exercised via `test_display_inky.py` with `_push_to_panel` mocked out so the retry/error paths run without real hardware; it deliberately stays *in* coverage (only `tests/*` is omitted in `tool.coverage.run`), with `pragma: no cover` suppressing the hardware-only branches. `inky_buttons.py` is tested with `gpiozero.Button` stubbed via a `FakeButton` class injected through `sys.modules`. `probe_buttons.py` has a smoke-test module (`test_probe_buttons.py`) that mocks GPIO interaction. `tests/test_path_resolution.py` pins all four branches of `resolve_input_path` (absolute passthrough, CWD hit, bundled fallback, missing-everywhere) — the CWD-vs-`BASE_DIR` asymmetry documented under "Default paths" is easy to "tidy" wrongly, and the bundled fallback is what lets the shipped `config.toml.defaults` keep portable relative strings.

**Renderer golden-image suite (`tests/test_render_golden.py` + `tests/golden/renderer/*.png`).** 86 committed PNG fixtures: a hand-written set spanning every layout × mode combination (hero/standard/dense × default/dark × production/debug/card) plus the `fallback_debug_default` arrow-form footer and a `no_metadata_production` attribution-skipped edge case, and a generated `standard_<theme>_production` scenario for **every** registered theme. The theme sweep is generated rather than hand-listed so a newly registered theme arrives with a failing golden test ("golden was missing; wrote a new fixture") instead of shipping unpinned; `test_every_registered_theme_has_a_golden` fails if a future refactor filters themes back out. Two themes read the wall clock — `astrarium` prints the date in its header and derives its solar/lunar datums from the day of year, `vinyl` stamps a copyright year and seeds its sleeve wear-speckle from `YYYYMMDD` — so their comparison runs under `_frozen_clock()`, which swaps `render_quote.datetime` for `datetime` subclasses overriding only `now()` / `today()`. Without that freeze neither theme could have a fixture at all (it would expire overnight), which is why neither had one. `test_clock_dependent_theme_list_is_accurate` re-renders every theme at two instants and fails if `CLOCK_DEPENDENT_THEMES` is wrong in either direction: an unlisted clock reader makes CI expire overnight, an unnecessarily frozen theme hides a real dependency change. Each scenario is re-rendered in-process and compared pixel-by-pixel against its golden via `ImageChops.difference`; `MAX_DIFF_RATIO = 0.001` (0.1% of 384,000 pixels) tolerates a one-pixel antialiasing boundary while catching layout, bold-phrase, and accent-colour regressions that flip thousands of pixels. Robust across FreeType / Pillow drift because `snap_image_to_palette` collapses every output pixel to one of six fixed Spectra 6 triples — subpixel drift generally rounds to the same palette index. Regenerate after an intentional renderer change with `UPDATE_RENDER_GOLDEN=1 pytest tests/test_render_golden.py`; a structure test fails if an orphaned fixture lingers after its scenario is deleted.

**Per-theme decoration fences (`tests/test_theme_decoration.py`).** The 37 border-painted themes in `_BORDER_PAINTERS` and 42 `render_*_frame` compositions are ~61% of `render_quote.py` and ~38% of the repo's production Python, and for most themes they used to be *executed* by tests without being *asserted on*: `TestPreviewSizeRendering` renders every registered theme at 80×60 and 240×144 checking only `img.size` and palette-subset, which walks every painter (so line coverage read ~95%) while saying nothing about what it drew. A mutation probe measured the gap — replacing all the border painters then in the tree (33 of them) with `lambda *a, **k: None` left 17 with a fully green suite, and neutering the custom-frame sub-painters left six frame themes (astrarium, chrono, grimdark, lcars, letter, questline) undefended.

The fences are structural rather than one bespoke assertion class per theme. `TestBorderPainterActuallyPaints` renders each theme twice — once with its painter neutered — and requires a meaningful pixel delta concentrated in the outer margin band. **Both dispatch paths must be patched**: the five `_CLEAR_RECT_PADS` themes (blueprint / kanagawa / cartograph / circuit / letter) are called by name from `render` so the body-text knockout rect can be threaded through, and patching only `_BORDER_PAINTERS` makes kanagawa and letter report a 0-pixel delta while their painters are still running. `TestCustomFrameCompositionPaints` does the same via each frame's `_<theme>_paint_*` helpers, plus a fence on that naming convention so a rename can't empty the neuter set and turn the test into a vacuous pass. `TestThemeDecorationRegistry` requires every theme to be in exactly one of border-painted / custom-framed / deliberately-plain (`default`, `dark`), and cross-checks the frame list against `render`'s dispatch ladder.

Thresholds are loose floors read off the measured spread, not golden values — the quietest border is `swiss` (783 px total, 90 in the margin band; its whole decoration is one hairline plus a 6×6 square by design). This suite answers "did the painter paint at all"; the golden fixtures answer "did it paint the same thing as before", so a legitimate visual tweak re-baselines a PNG instead of re-tuning a pixel count here.

**Documented-theme-count fence (`tests/test_docs_theme_counts.py`).** CLAUDE.md, README.md and CONTRIBUTING.md each restate registry facts in prose — how many themes are registered, how many bypass the literary layout, which themes button B cycles through, and the full roster in three separate places — and every one of them had drifted at least once. The two failure modes are independent, which is why both are fenced: the README's count sentence correctly said "Sixty-three themes ship built-in" while the reference list beside it named sixty-two, silently omitting `bakelite`; and CLAUDE.md's decoration paragraph claimed 33 border painters and thirteen frame compositions against an actual 36 and 25. Counts are compared against `len(THEMES)` / `len(_BORDER_PAINTERS)` / `len(CUSTOM_FRAME_THEMES)`, spelled through a small `spell()` helper so `twenty-five` is checked as a number rather than as a string; rosters are compared against `THEME_ORDER` and `theme_cycle()` as ordered lists.

**A prose regex that matches nothing must fail, not pass.** `_find` fails loudly with the pattern and the sentence it was looking for, so rewording a fenced sentence costs a deliberate update here rather than silently retiring the check — the vacuity trap `TestTarotEmblems`'s clip assertion and `TestAutochromePlate`'s texture assertion both fell into. That is the whole reason a *count* is worth fencing where the retired per-theme ordinals were not: one number, in one place, against a list that already exists in code. Verified by mutation against ten reintroduced faults (a theme dropped from each roster, each count off by one, a fenced sentence reworded away) and against the normal trigger — a theme added to `THEMES` with the docs left alone, which fails all eleven applicable assertions.

**Pixel assertions go through `tests/pixel_helpers.py`.** Image tests never call `Image.getdata()` — Pillow deprecated it and removes it in Pillow 14 (2027-10-15), and its replacement `get_flattened_data()` only exists from Pillow 11.1, so *both* APIs tie the suite to a version window. The helper module exposes the three shapes the assertions actually need, all built on APIs stable across every Pillow release:

- `distinct_inks(img)` → `set` of RGB tuples, via `getcolors(maxcolors=w*h)` (the cap guarantees a non-`None` return — an image cannot hold more distinct colours than it has pixels). This is the overwhelmingly common case: "is this frame on-palette", "did the border surface all six inks". Those assertions are about *which* inks appear, not about walking 384,000 pixels in order, so `getcolors` is the better semantic fit as well as the portable one.
- `ink_counts(img)` → `{colour: count}` histogram, for ratio checks like circuit's forest-wash green/black balance. Note it is a plain dict, not a `Counter` — ask with `.get(ink, 0)`, because a missing key is the honest answer for an absent ink.
- `pixel_bytes(img)` → `tobytes()`, for the determinism checks (`render` twice, assert byte-identical). `getcolors` is unordered and cannot serve these; a site that compares full pixel *sequences* must use this, never `distinct_inks`.

`tests/test_render_golden.py::_diff_pixels` uses a fourth form — `convert("L").histogram()[1:]` summed — to count differing pixels in the diff bbox.

The floor in `pyproject.toml` is `Pillow>=9.3` rather than the `>=11.1` a `get_flattened_data` migration would have forced: nothing here calls that API, 9.3 is the oldest release the suite is verified green on under `requires-python >= 3.11`, and an 11.1 floor would lock out the distro Pillow on Raspberry Pi OS bookworm (9.4) — the appliance's own deployment target. The binding production API is the `Image.Dither` enum (Pillow 9.1.0). The scoped `error:.*will be removed in Pillow.*:DeprecationWarning` filter (see pyproject notes above) is what keeps a reintroduced `getdata()` from silently accruing again.

**Curator UI JavaScript suite (`tests/js/` + `tests/test_web_ui_js.py`).** `idle_hours/web/main.js` is 726 lines of operator-facing behaviour no Python test can reach: hash routing, the lazy per-tab fetch gating, the focus guard that stops the 30 s poll from collapsing an open theme dropdown, 401 token recovery, and the overrides editor's `If-Match` save plus `banQuoteKey`'s key-only ban POST — the two paths that write the shared `selection_overrides.json` sidecar, where a bug silently drops an operator's bans and boosts. `tests/js/harness.mjs` loads the **real** `main.js` into a `node:vm` sandbox with a minimal DOM stub, so there is no transcribed copy to drift out of sync with the served file. `main.js` declares everything with `const` / `function` at top level and only calls `init()` from a `DOMContentLoaded` listener, so loading it is side-effect free; a bridge script run in the same context lifts the lexical `const` bindings onto the global object and throws if a name it expects no longer exists rather than exporting `undefined`. `tests/test_web_ui_js.py` bridges the suite into pytest, skipping when node is absent (node is not a project dependency) — the `web-ui-js` CI job runs `node --test` directly so that skip can never hide a regression, and `TestJsSuiteWiring` asserts the run reports a non-zero passing count since `node --test` exits 0 when it matches no files.

**Packaging-boundary tests (`tests/test_packaging.py`).** Two install-time invariants that `pip install -e .` (the developer setup, which puts the repo on `sys.path` regardless of how `setuptools.packages.find` is configured) cannot see: (1) the wheel ships every `idle_hours/*.py` module **plus** the bundled static trees — `[tool.setuptools.packages.find]` must `include = ["idle_hours*"]` and `[tool.setuptools.package-data]` must ship `assets/**` / `fonts/**` / `web/**`, since setuptools ships exactly what those declare and a module/asset that doesn't end up in the wheel silently breaks the installed app; (2) importing any production module never pulls hardware deps (`gpiozero` / `inky` / `RPi.GPIO`) into `sys.modules`. The second check runs each module import in a subprocess so prior in-process imports can't pre-populate the namespace and mask the leak. Both invariants are also enforced at CI time by the `package-build` job (see "CI" below).

**Scorer property tests (`tests/test_scorer_properties.py`).** Complements the ordinal checks in `test_scorer_invariants.py` with systematic sweeps that would catch mutations the pairwise tests miss. Locks: tuple layout (length 12, `minute_penalty` at position 2, `override_bonus` at position 7, bake-component parity with `BAKED_SCORE_COMPONENTS`); lexicographic dominance (an earlier-position row wins against any later-position delta, no matter how large); strict monotonicity in quality across the full 0..100 sweep; minute-penalty dominance over metadata / dialogue / quality; `preferred_buckets` beats `boost_source_ids`; position isolation (each component only moves its own tuple slot — a refactor that leaks into two positions fails); request-time recomputation (only `minute_penalty` and `override_bonus` change as `requested_time` / `overrides` vary — the contract baked-row caching relies on); baked/raw interleave equivalence across five corner-case row shapes; exhaustive minute-distance sweep for every (requested, quote) pair in [0..55] step 5; and scoring purity (no mutation of the row dict or the overrides dict). Follows `test_buckets_properties.py`'s pattern — exhaustive enumeration over bounded spaces, no Hypothesis dependency.

**Test structure:**
- `tests/conftest.py` — shared fixtures: `make_row()` factory, `sample_row`, `sample_rows`, and `tmp_jsonl` (a helper that writes a list of dicts to a temp JSONL file). Also installs an autouse `_isolate_home` fixture that monkeypatches `$HOME` to a per-test tmp dir, so tests that use default `--state-path` / `--history-path` / `--pidfile` / `--telemetry-path` values can't leak state into the developer's real `~/.idle-hours/` or contaminate each other within a run.
- One `test_<script>.py` module per main script; tests are class-based (e.g., `TestCurrentBucket`, `TestRenderNow`)

**pyproject.toml** configures:
- `[project]`: name `idle-hours`, **version — the single source of truth for the release number** (`idle-hours --version` reads it back through `importlib.metadata`, so this literal is what the CLI, the wheel filename, and `pip show` all report). It sat at the `0.1.0` scaffold placeholder through the v1.0.0 / v1.1.0 / v2.0.0 tags, so every released wheel identified itself as 0.1.0 (issue #180). Keep it in lockstep with the git tag: the CI `release-version` job fails a `vX.Y.Z` tag build whose ref disagrees, and `tests/test_packaging.py::TestReleaseVersion` pins the shape plus agreement with the installed dist metadata. `requires-python >= 3.11`, runtime dep `Pillow>=9.3` (a floor, not a pin — see "Pixel assertions" under Testing for why it is 9.3 and deliberately not 11.1), optional extras `dev = [build, pytest, pytest-cov, pytest-xdist, pyyaml, ruff]` and `pi = [inky, gpiozero]` (`build` powers the local release tool's isolated wheel verification; `pyyaml` is test-only — `tests/test_ci_required_checks.py` parses `.github/workflows/ci.yml`) (`gpiozero` is needed by `inky_buttons.py` on the Pi). `pip install -e .[dev]` is the intended developer setup.
- `[tool.setuptools.packages.find]` (`include = ["idle_hours*"]`) + `[tool.setuptools.package-data]` (`idle_hours = ["assets/**/*", "fonts/**/*", "web/**/*"]`): the source of truth for what the wheel carries. Every production module now lives under the `idle_hours/` package, so setuptools discovers them automatically — no flat `py-modules` list to keep in sync (the project switched away from that form so the wheel could carry the static trees as package-data). A bundled asset tree missing from `package-data` silently breaks `pip install .` (the CLI 404s the curator UI, falls back to bitmap fonts, can't find the corpus). `tests/test_packaging.py::TestPackageDeclaration` and the CI `package-build` job both fence this.
- pytest: `testpaths = ["tests"]`, `python_files = ["test_*.py"]`, `python_functions = ["test_*"]`, and a two-entry `filterwarnings`: the blanket `ignore::DeprecationWarning` (third-party noise) followed by `error:.*will be removed in Pillow.*:DeprecationWarning`. Later filters win in pytest, so Pillow's own removal notices are promoted back to hard failures while everything else stays quiet. The blanket ignore alone let 26 `Image.getdata()` call sites accrue against a Pillow 14 removal for a year (issue #204) — the scoped `error` entry is what makes the next one fail on the day it lands.
- coverage: source = `.`, omits `tests/` and `bootstrap_pi_inky.sh`. `display_inky.py` deliberately stays in coverage — its module-level defaults + `resolve_saturation` + `main()` retry/backoff logic are exercised by `tests/test_display_inky.py` with the hardware call (`_push_to_panel`, which imports the Pimoroni Inky library) mocked out. `[tool.coverage.report] exclude_lines` keeps the default `pragma: no cover` marker (overriding the list without re-adding it would silently disable hardware-only branch suppression).
- ruff: line-length 130, target Python 3.11, rules E / W / F / I (E501 ignored)

**CI:** `.github/workflows/ci.yml` runs on pushes to `main`, on `v*` tags, and on every pull request — feature branches get checked via the `pull_request` trigger only, so `push` + `pull_request` don't double-run. Seven jobs:
- `lint` — single Python 3.12 job running `ruff check --output-format=github .` once, so style feedback lands as inline PR annotations without waiting for the test matrix.
- `test` — matrix across Python 3.11 / 3.12 running `pytest -n auto --dist loadscope --ignore=tests/test_render_golden.py`. Both legs run plain pytest at the same speed; the 3.11 leg is a regression tripwire for the older interpreter. The 3.12 leg also runs an end-to-end `idle-hours run --once --skip-preflight` step that verifies the resulting `output/current.png` decodes via `Image.verify()`, so a truncated / partially-snapped PNG surfaces in CI rather than on the appliance.
- `coverage` — Python 3.12 + `COVERAGE_CORE=sysmon` (PEP 669) running pytest with `--cov-branch --cov-fail-under=95` and uploading `coverage.xml` as the `coverage-3.12` artifact with `if-no-files-found: error`. Lives in its own job because branch-coverage tracing still has measurable overhead even under sysmon, and the previous "coverage piggybacks on the 3.12 test leg" layout was serialising the test matrix behind that overhead. Runs on `pull_request` as well as `push` so a regression is visible before merge, but is deliberately **advisory** because its tracer-heavy full-suite run can take roughly ten minutes. The 95% floor still turns the job red; it simply does not disable the merge button.
- `golden-render` — splits the renderer golden-image suite (`tests/test_render_golden.py`) into its own job so its in-process Pillow renders don't serialise behind the main test matrix; run with `-n auto --dist worksteal`. Also runs `scripts/generate_theme_previews.py --check`, which re-renders every README thumbnail and fails if one has gone stale — the docs fences check only that a preview *file exists* per theme, never that its contents still match the renderer, which is how the `betweenus` chip stayed green in the README after the theme stopped painting it green (issue #257). It compares against the **same budgets as the golden suite** (0.1%, 0.15% for `diags`), mirrored in the script and fenced against divergence by `TestToleranceMatchesTheGoldenSuite`; an exact-zero comparison was the first cut and is wrong for the reason `SCENARIO_MAX_DIFF_RATIOS` exists — a Pillow/FreeType point release moves `diags`'s small DejaVu labels by ~0.14% of the canvas, and CI resolves Pillow at install time against a `>=9.3` floor, so it would redden a required job across every open PR the day a release lands (the flake PR #229 hit once). The budget is 384 pixels of 384,000, so this catches theme-scale staleness — a palette change, a new border painter, a font swap — and **not** a single small ornament: the `betweenus` chip itself moved 61 pixels and sits under it, exactly as it sat under the golden fixtures' identical budget. A change that small needs the eye or a targeted assertion. Folded into this job rather than given its own so `.github/rulesets/main-branch.json` needs no change; it costs ~17s against the job's 10-minute budget.
- `web-ui-js` — runs the curator UI's JavaScript suite (`node --test tests/js/*.test.mjs`) on Node 22. No dependencies and no build step: `tests/js/harness.mjs` loads the real `idle_hours/web/main.js` into a `node:vm` sandbox with a DOM stub, so there is no transcribed copy to drift. `tests/test_web_ui_js.py` bridges the same suite into pytest but *skips* when node is absent, which is exactly why this job exists — a missing interpreter must fail the build rather than turn the JS suite into a silent green skip. Test files are passed explicitly because without a root `package.json`, `node --test tests/js/` resolves the directory as a module entry point and dies with MODULE_NOT_FOUND before running anything.
- `package-build` — builds a wheel + sdist via `python -m build`, installs the wheel into a fresh venv with **no extras** (no `[dev]`, no `[pi]`), then imports every `idle_hours.*` production module from the installed wheel and asserts (a) all imports resolve under `site-packages` (not the source checkout — the import step `cd`s to `/tmp` so `sys.path[0]` doesn't shadow the wheel), (b) the bundled `assets/` / `fonts/` / `web/` trees are present next to the installed modules (package-data shipped), and (c) no `gpiozero` / `inky` / `RPi` leaked into `sys.modules`. Finally smoke-tests `python -m idle_hours.run_clock --help`.
- `release-version` — tag-only (`if: startsWith(github.ref, 'refs/tags/v')`). Asserts the pushed `vX.Y.Z` ref matches `[project].version` in `pyproject.toml` and fails the build otherwise, so a release can't ship wheels whose metadata disagrees with the tag (issue #180). There is nothing to compare against on a branch push or a PR, hence the guard. This catches the install-time failure modes that `pip install -e .` cannot: modules missing from `packages.find`, missing/mispatterned `package-data`, optional-dep leakage at module import time, and broken `__main__` wiring.

**Required status checks (`.github/rulesets/main-branch.json`).** The required checks are `lint`, `test (3.11)`, `test (3.12)`, `golden-render`, `web-ui-js`, and `package-build`. `coverage` also runs on every pull request but is deliberately advisory because of its roughly ten-minute runtime; `release-version` is advisory because it is tag-only and reports `skipped` on pull requests. Both are explicit entries in the test's `ADVISORY_JOBS` map rather than implicit exceptions. A job-level `if:` is deliberately *not* grounds for automatic exemption — a future job conditioned on something that can be true on a PR would really run and could really fail. The ruleset previously required only `lint` and the two `test` legs (issue #241), which left advisory exactly the jobs that exist *because the `test` matrix structurally cannot catch what they catch*: `web-ui-js` is the only thing that actually runs the curator UI's JS (its pytest bridge lives inside required `test (3.12)` and goes green on a skip when node is absent — the failure that job was written to prevent); `package-build` is the only guard on install-time failures the `pip install -e .` everything else uses cannot see; `golden-render` is the only guard on the 63 PNG fixtures, and it is what turned `main` red after #217 merged. `tests/test_ci_required_checks.py` fences the workflow against the ruleset as a **set equality**, so a new CI job fails the suite until someone classifies it. It also refuses to guess at anything it cannot model — an explicit `name:` (which overrides the job id as the context, so ignoring it would leave the ruleset requiring an id nothing reports, the one case that really does block every merge), a matrix `include` / `exclude`, or an unresolved `${{ }}` expression each fail the fence with an instruction rather than silently narrowing what it covers. Two caveats the test cannot cover: the committed JSON is a description of intent until it is pushed to GitHub (`.github/rulesets/README.md` has the `gh api` command), and `strict_required_status_checks_policy` stays `false` — no list of required contexts can prevent the semantic-merge failure that reddened `main` after #217, since every context passed on that PR's own head; only requiring PRs to be current with `main` addresses it, at the cost of a rebase and a full CI re-run on every out-of-date PR.

The `lint` / `test` / `coverage` / `golden-render` jobs install via `pip install -e ".[dev]"` (single source of truth with `pyproject.toml` — no hardcoded `pytest pytest-cov ruff Pillow` list to drift); `package-build` is the deliberate exception, installing the built wheel into a fresh venv with no extras so the wheel-install semantics are exercised end-to-end. All five jobs enable `actions/setup-python`'s pip cache keyed on `pyproject.toml`, set `timeout-minutes` as a hang safety-net, and run with `permissions: contents: read` (least-privilege `GITHUB_TOKEN`). A top-level `concurrency` group cancels superseded PR runs (`cancel-in-progress` only when `github.event_name == 'pull_request'`) so `main`-branch history is preserved while rapid PR pushes don't pile up. The test matrix runs with `fail-fast: false` so one Python version failing doesn't hide the other. Keep imports sorted (rule I) — run `ruff check .` locally before pushing.
